어떤 문제를 다뤘나요?

AI 활용 사례는 빠르게 쌓이지만, 글 목록만 보고서는 어떤 내용을 먼저 배워야 할지 알기 어렵습니다. 이미 읽은 자료와 주제 간 선행관계를 바탕으로 다음에 읽을 글을 추천하는 서비스를 만들었습니다.

콘텐츠는 수집 → 품질 검사 → 태깅·임베딩 → 그래프 편입 → 추천 순서로 흐릅니다. LLM 호출은 태깅·주제 이름·추천 근거 문장에만 쓰고, 그래프 구조와 추천 점수는 코드가 계산합니다.

문제 해결

콘텐츠 66%가 대주제 7개에 몰린 catch-all 문제를 k-means 잔여 분할로 해소

문제 원인

  • 2패스 구조를 적용한 뒤에도 콘텐츠의 66%(764건)가 하위 주제 없이 대주제 7개에 직접 연결돼 있었습니다.
  • 잔여 콘텐츠를 연결요소로 묶는 방식은 거대한 한 덩어리가 되거나 전부 고아가 되는 양극단으로 갈라졌습니다.
  • 추천의 선행관계 경로 점수가 대표 노드를 찾지 못해 모두 중립값(0.5)으로 계산됐습니다.

해결 과정

  • catch-all 기준 재정의: 하위 노드에 속하지 않고 대주제에 직접 붙은 잔여 콘텐츠를 기준으로, 여러 번 실행해도 같은 결과가 나오게 재분할했습니다.
  • 균형 분할: 연결요소 묶기 대신 spherical k-means(k = round(n/45))를 썼습니다.
  • 이상치 가드: 중심 유사도 0.45 미만인 콘텐츠는 강제 편입하지 않고 새 주제 후보로 남겼습니다.
  • 회귀 게이트: 그래프를 다시 만들 때 목적함수 J가 0.02 넘게 떨어지면 실패하도록 했습니다.
  • 테스트: test_auto_hkg 22개를 포함해 전체 372개가 통과했습니다. 로컬 재구축 DB에서 전후를 측정했습니다.

결과

  • 하위 주제 노드 68개가 생겼습니다(예: 'AI 메모리&상태관리', 'Claude Code 실전활용').
  • coverage가 0.34 → 0.999, 그래프 목적함수 J가 0.525 → 0.689로 올랐고, 고아 노드는 0개입니다.
  • 선행관계 경로 점수가 추천 후보 400개 중 292개에서 작동하게 됐습니다.

기존 주제부터 확인하는 2패스

기존 주제에 들어갈 글을 먼저 편입하고, 남은 글만 유사도에 따라 묶어 새 주제를 만들었습니다. LLM에는 군집 이름과 설명을 요청했습니다.

주제별로 편입 임계값 계산

다른 주제의 글과 주제 중심 사이의 유사도를 모아 95번째 백분위수를 구했습니다. 하한은 0.62로 두고 비교 표본이 없으면 고정 임계값을 사용했습니다.

하위 주제에서 선행관계를 먼저 조회

하위 주제에 선행관계가 없으면 부모 주제에서 조회했습니다. 학습 상태에 따라 선행 충족 점수를 계산해 추천 순위에 반영했습니다.

새 글마다 주제 노드가 생겨 관련 자료가 흩어졌습니다. 기존 주제에 먼저 편입하고 남은 글을 묶는 2패스로 바꾼 뒤 콘텐츠 924건을 재구축하자 자동 생성 주제가 825개에서 24개로 줄었습니다. 별도의 시간순 유입 실험에서는 콘텐츠 902건에 고정 기준과 동적 기준을 각각 적용했습니다. 기존 주제에 편입되지 않아 후속 군집화로 넘어간 글은 717건에서 534건으로 줄었습니다.
